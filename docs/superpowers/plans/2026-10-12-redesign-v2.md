# Redesign v2 + LLM brief Implementation Plan

> **For agentic workers:** this plan runs in the project's multi-agent workflow
> (`docs/workflow.md`): ing-lead does the L tasks on `main`; each worker does its
> tasks test-first in its worktree and reports "milestone <n> done, tests green,
> <branch>@<sha>". Steps use checkbox (`- [ ]`) syntax. Read `docs/web-ui.md`
> sections "Redesign v2" and "LLM brief" (the spec) and the mockup
> `docs/web-ui/mockups/redesign-v4.html` (tab 3 "B4", tabs 4 and 5 option "A")
> before your first task.

**Goal:** Rebuild the three screens as approved on 2026-10-12 (dashboard B4,
fund card as a side panel, meeting text as a document) and add an LLM brief to
the dashboard.

**Architecture:** Contract v1.4 adds `NarrativeBrief` and `Backend.brief`;
`RealBackend` starts the TR brief in the background when it makes a ready run;
the narrator writes it with Claude Haiku 5.5 under the existing validator rules,
with a plain sentence as fallback. The API adds short names to `OptionView` and
`GET /api/runs/{id}/brief`. The web app replaces its dashboard, fund card and
meeting text views; the data of the other endpoints does not change.

**Tech Stack:** Python 3.11+, FastAPI, pytest; React 18, TypeScript, Tailwind 3,
Vite 8, Vitest 5, Testing Library.

**Spec:** `docs/web-ui.md` — "Redesign v2" and "LLM brief" (they win over the
older screen sections).

## Global Constraints

- Every task ends with green `pytest`; web tasks also with green `npm test` and `npm run build`; no test touches the network.
- Contract v1.4 is additive: new types and fields have defaults; v1.3 JSON still loads.
- ING orange `#FF6200` only for the brand and the one filled button of a screen; text `#1D2440`; chart cobalt `#4676BF`; category grey `#D0D5DD`.
- 24 px between sections; values in tables left-aligned with tabular figures.
- "Öneriler" view switch: `Tablo | Kartlar`, default `Tablo`, remembered in local storage (`rmprep.view.oneriler`).
- Short names: issuer = words up to and including "PORTFÖY" (title case); fund type = the rest without "FONU" (title case, Turkish rules); "KISA VADELİ" → "KV", "BORÇLANMA ARAÇLARI" → "Borçlanma"; full label on hover.
- Brief: 1–2 sentences, at most 280 characters, for the RM; model `claude-haiku-5-5`; no retry; fallback = `durum` + `yatirim_amaci`; never in the card or the meeting text.
- Open "Teyit edin" items remind ("k konu teyit edilmedi"); they do not block approval.
- At most 3 working sessions, the lead included.

## Review Focus

1. **A persona name or label with Turkish dotted / dotless i** ("İSTANBUL", "KATILIM", "BİRİNCİ"): short names keep correct Turkish case ("İstanbul Portföy", "Birinci"). Test: L12 `test_short_name_turkish_case`.
2. **A label without "PORTFÖY"** (time deposit, deposit, an unusual fund name): no issuer, the whole label as the short name, nothing crashes. Test: L12 `test_short_name_without_portfoy`.
3. **The brief is still running or fails** (slow call, no key, validator rejects it): the dashboard shows the plain sentence at once and does not wait; a failed brief keeps the plain sentence with no "AI özeti" label. Tests: L11 `test_brief_running_202`, W10 `keeps the plain sentence when the brief fails`.
4. **A `needs_rm_input` run**: no brief call, no Öneriler table; the questions take its place. Tests: L11 `test_no_brief_for_needs_input`, W7 `needs_rm_input shows questions instead of Öneriler`.
5. **Fewer than 3 recommendations** (a strict persona or excluded sources): the table and the cards show the columns that exist, the deposit column stays last. Test: W7 `table with one recommendation`.

```python
@dataclass(frozen=True)
class NarrativeBrief:
    run_id: str
    lang: str                       # "TR" | "EN"
    text: str                       # 1-2 sentences, <= 280 characters
    source: str                     # "llm" | "template"
    model: str                      # "" for the template
    prompt_version: str
    checks: tuple[str, ...]         # validator findings / errors; () = passed
    created_at: datetime            # timezone-aware
    cost_usd: float = 0.0
    cite: tuple[str, ...] = ()      # evidence ids and option ids it rests on

# Backend protocol:
def brief(self, run_id: str, lang: str = "TR") -> NarrativeBrief | None:
    """The brief of a ready run; None while its background job runs (it starts
    the job if needed). A needs_rm_input run raises ValueError."""

# rmprep.narrator.template (lead adds it in this task; N10 may move it):
def plain_brief(r: DecisionResult, lang: str) -> str   # durum + yatirim_amaci, TR or EN frame
```

- API: `GET /api/runs/{id}/brief?lang=TR` → 200 `NarrativeBrief.to_dict()` | 202 `{"status": "running"}` | 404 unknown run | 422 needs_rm_input.
- RealBackend: after a **new** ready run in `_run`, submit `self._brief_now(run_id, "TR")` to the existing pool; `_brief_now` calls `self._narrator().brief(result, evidence, lang)` if the narrator has `brief` (after N10), else returns the template brief (`plain_brief`).
